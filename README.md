## О расширении

**DashBridge** - расширение для инженеров сопровождения и мониторинга. Оно объединяет нужные графики Grafana в одном дашборде, позволяет фильтровать и преобразовывать метрики, контролировать пороговые значения и массово сохранять снимки за выбранные периоды.

Дополнительные модули помогают вести Worklog в Jira, экспортировать переписку из TDM Chat и устраняют проблему с прокруткой в редакторе Confluence.

> DashBridge работает поверх уже открытых корпоративных сервисов и использует действующую браузерную сессию пользователя. Отдельный сервер DashBridge не требуется.

## Возможности

### Единый дашборд Grafana

Собирайте панели из разных дашбордов Grafana на одной странице и формируйте собственные рабочие представления.

- несколько независимых профилей с собственными панелями и диапазонами времени;
- добавление панели по Embed URL или быстрое добавление нескольких панелей по ID;
- настройка ширины и высоты карточек, изменение порядка перетаскиванием;
- полноэкранный режим для отдельного графика;
- единый диапазон времени и автообновление внутри каждого профиля;
- светлая, тёмная или наследуемая тема Grafana;
- пауза отдельных панелей без удаления их настроек;
- синхронный курсор между графиками;
- экспорт и импорт профилей в JSON;
- быстрые ссылки на часто используемые дашборды.

### Сводные сообщения и SLA

Общий шаблон создаётся автоматически и при необходимости редактируется на уровне профиля. У каждого графика есть отдельная кнопка настройки его фразы: пользователь выбирает участие панели и редактирует два понятных результата — «требования соблюдены» и «требования нарушены».

- порог и единица измерения автоматически получаются из Grafana; при необходимости можно задать отдельный SLA или информационный режим без SLA;
- готовое сообщение формируется одной кнопкой в шапке сводного дашборда;
- три состояния результата: норма, предупредительный уровень и критическое нарушение;
- условия выше/ниже порога и расчёт по максимуму, минимуму, среднему, сумме либо последнему значению;
- вывод панели всегда, при warning/нарушении или только при критическом нарушении;
- настраиваемые строки списков серверов и отдельный цитатный блок подробностей;
- переменные для critical/warning-списков, агрегатов, периода и названия панели;
- контекст теста: название, окружение, время начала и длительность стабильной нагрузки;
- emoji-индикаторы, редактируемый предпросмотр и копирование готового сообщения;
- недоступные и приостановленные панели явно отмечаются и не считаются успешно прошедшими SLA.

### Инструменты для графиков

Настройки применяются к выбранной панели и сохраняются вместе с профилем.

- удаление заливки и увеличение толщины линий;
- изменение порядка легенды;
- фильтрация отображаемых Series по названию;
- отбор Series по максимальному или последнему значению;
- визуальное выделение значений, превышающих заданный порог;
- пороговые уведомления для выбранных графиков;
- преобразование CPU `Idle → Load`;
- преобразование RAM `Total / Available → % Used`;
- фильтрация Load Average относительно доступного количества vCPU;
- сохранение или копирование снимка отдельной панели;
- компактный режим снимка с фиксированным размером результата.

### Анализ CPU и RAM

На панелях `CPU Usage` и `Memory` доступна кнопка анализа без ручного разбора легенды. Она также работает для названий с суффиксом `calculated`.

- анализ данных за весь выбранный период или по последнему значению;
- сортировка серверов по загрузке CPU и использованию RAM;
- цветовая индикация настраиваемых порогов;
- копирование полного результата или TOP-3 по готовому шаблону;
- настройка ключевых слов метрик и форматов отчёта.
- автоматическое обновление сводки вместе с datasource-ответами Grafana.

### Массовый сбор снимков Grafana

Batch-модуль автоматизирует подготовку большого количества изображений для отчётов и разборов инцидентов.

- автоматическое получение списка панелей дашборда;
- сбор всех панелей, белого списка или всех панелей кроме исключённых;
- несколько временных диапазонов за один запуск;
- относительное время (`now-1h`, `now`) и абсолютные даты разных форматов;
- выбор светлой, тёмной или текущей темы;
- отдельные правила обработки для конкретных ID панелей;
- групповой снимок выбранных Series или отдельный файл для каждой Series;
- фильтры включения и исключения Series по ключевым фразам;
- упаковка результатов и отчёта об ошибках в ZIP-архив;
- прогресс выполнения, журнал и безопасная отмена операции.

### Снимки и экспорт

- сохранение одной панели в PNG;
- копирование изображения панели в буфер обмена;
- сохранение всех активных панелей профиля одним ZIP-архивом;
- компактный формат снимков для документов и отчётов;
- пакетный экспорт панелей и изолированных Series по временным срезам.

### Traffic Recorder

Recorder создаёт отдельную контролируемую Chrome-вкладку и связывает действия
пользователя с её сетевым трафиком через Chrome DevTools Protocol.

- запись переходов, кликов, ввода, select/checkbox и управляющих клавиш;
- HTML, JavaScript, CSS, fonts, images и XHR/fetch с headers и ограниченными bodies;
- сохранение действий в `flow.json`, канонического CDP-трафика в `network.json`, HAR 1.2, потоковых событий и response bodies в переносимый `.dashflow` v2;
- загрузка ранее сохранённого `.dashflow` и последовательный replay;
- независимый `Disable Cache`: browser и Service Worker cache обходятся;
- независимый `Disable Cookies`: сценарий запускается в чистом incognito-окне, cookies живут только внутри запуска;
- таблица baseline/replay с подсветкой изменённых, добавленных и удалённых запросов;
- явные статусы полноты request/response bodies и ограниченные WebSocket/SSE/WebTransport-события для будущих HAR/JMX/WebPageTest-конвертеров;
- пароли, cookies и токены сохраняются открыто, поэтому `.dashflow` нужно хранить как файл с учётными данными;
- запись ограничена созданной Recorder-вкладкой и завершается при Stop или закрытии страницы Recorder.

### Jira Worklog

Встроенный менеджер помогает подготовить несколько записей времени и отправить их в Jira одной операцией.

- таблица черновиков Worklog;
- получение названий задач по ключу Jira;
- группировка записей по датам;
- подсчёт часов за день и неделю;
- клонирование, сортировка и очистка отправленных записей;
- пакетная отправка подготовленных записей;
- копирование или перенос Worklog из текущей задачи Jira в другую;
- настраиваемый адрес Jira и часовой пояс.

### Confluence

Опциональное исправление предотвращает прыжок страницы вверх при клике в пустую область редактора Confluence.

- включается и выключается из popup-окна;
- работает только на разрешённых Wiki-доменах;
- поддерживает настраиваемые идентификаторы iframe редактора.

### TDM Chat

- экспорт сообщений за выбранный период;
- форматы HTML, JSON или оба одновременно;
- сохранение фотографий в отдельный ZIP-архив;
- исключение фотографий выбранного пользователя;
- сохранение последних параметров экспорта.

### Диагностика Grafana

Для поиска проблем предусмотрен отдельный диагностический раздел.

- сведения о версии и окружении Grafana;
- диагностика структуры панелей, canvas, легенд и DOM;
- сбор снимков интерфейса в ZIP;
- встроенный E2E Test Runner для проверки совместимости.

Диагностический отчёт не копирует cookies, содержимое запросов к источникам данных или сами данные дашборда.

## Типовой сценарий

1. Откройте настройки DashBridge и укажите адреса используемых сервисов.
2. Авторизуйтесь в Grafana в обычной вкладке браузера.
3. Откройте **Единый дашборд Grafana** из popup-окна расширения.
4. Создайте профиль и добавьте нужные панели через Share → Embed или по ID.
5. Настройте время, фильтры Series, преобразования и пороги.
6. Используйте дашборд для наблюдения или сохраните готовые снимки в PNG/ZIP.

## Установка

### Google Chrome

1. Скачайте репозиторий и распакуйте его в отдельную папку.
2. Откройте `chrome://extensions`.
3. Включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное расширение**.
5. Выберите корневую папку проекта, содержащую `manifest.json`.
6. Закрепите DashBridge на панели браузера.

### Microsoft Edge

Процесс аналогичен: откройте `edge://extensions`, включите режим разработчика и выберите **Загрузить распакованное**.

После обновления исходных файлов нажмите кнопку **Обновить** на карточке расширения.

При открытии popup проверяет последний стабильный выпуск в
[GitHub Releases](https://github.com/Phuoctonge/DashBridge/releases) не чаще
одного раза в 12 часов. Для более новой версии он показывает уведомление и
ссылку на ZIP, предварительно сверив тег, версию, имя файла и GitHub URL.
Отсутствие сети не мешает работе расширения. Это не автоматическая установка:
замените файлы распакованного расширения и нажмите **Обновить** в
`chrome://extensions`.

## Первичная настройка

Откройте popup DashBridge и нажмите значок шестерёнки.

| Раздел | Что настраивается |
|---|---|
| Интерфейс | Тема, запоминание активных вкладок, включение отдельных модулей |
| Grafana | Разрешённые домены, параметры URL, ключевые слова CPU/RAM, размеры снимков и пороги |
| Jira | Базовый URL, часовой пояс и значения Worklog по умолчанию |
| Confluence | Wiki-домены и идентификаторы iframe редактора |
| TDM | Адрес TDM Chat и параметры экспорта |
| Обслуживание | Экспорт, импорт и полный сброс настроек |

Настройки и пользовательские данные можно перенести на другой компьютер через экспорт и импорт конфигурации.

## Разрешения и данные

DashBridge предназначен для работы с корпоративными сервисами, адреса которых заранее неизвестны. Поэтому расширению требуется доступ к пользовательским HTTP(S)-сайтам.

| Разрешение | Для чего используется |
|---|---|
| `storage`, `unlimitedStorage` | Профили, настройки, Worklog, состояние Batch и диагностические данные |
| `activeTab`, `tabs` | Работа с выбранной вкладкой и временными вкладками Grafana |
| `windows` | Изолированные окна массового сбора и диагностики |
| `scripting` | Инструменты Grafana и действия на страницах Jira, TDM и Confluence |
| `downloads` | Сохранение PNG, ZIP, JSON и HTML |
| `clipboardWrite` | Копирование отчётов и изображений |
| `declarativeNetRequestWithHostAccess` | Безопасное встраивание разрешённых Grafana-панелей в DashBridge |
| `<all_urls>` | Поддержка произвольных корпоративных адресов Grafana, Jira, TDM и Wiki |

- настройки и рабочие данные хранятся в `chrome.storage`;
- собственный внешний backend и аналитика в расширении не используются;
- действия Jira и TDM выполняются только на настроенных адресах;
- инструменты Grafana активируются только для разрешённых доменов и маршрутов дашбордов;
- для доступа к сервисам используется текущая авторизованная сессия браузера.

Подробная карта разрешений находится в [docs/permission-map.md](docs/permission-map.md).

## Совместимость

- браузеры на базе Chromium с поддержкой Manifest V3;
- Grafana разных поколений: legacy Graph/Flot и современные Time series/uPlot;
- Jira с REST API v2 и авторизацией через текущую браузерную сессию;
- Confluence/Wiki с TinyMCE-совместимым iframe-редактором;
- TDM Chat на настраиваемом корпоративном домене.

Фактическая совместимость с Grafana зависит от версии, типа панели, темы и локальных модификаций интерфейса.

## Разработка

Проект не требует сборщика: интерфейс написан на HTML, CSS и JavaScript, а расширение загружается напрямую из исходной папки.

```text
DashBridge/
├── manifest.json            # Manifest V3
├── popup.html               # Главное popup-окно
├── dashbridge.html          # Единый Grafana-дашборд
├── batch.html               # Массовый сбор снимков
├── worklog.html             # Jira Worklog Manager
├── options.html             # Настройки расширения
├── js/
│   ├── content/             # Интеграция со страницами Grafana/Confluence
│   ├── pages/               # Логика полноразмерных страниц
│   ├── popup/               # Модули popup-окна
│   ├── shared/              # Общие компоненты и хранилища
│   └── test-runner/         # Диагностика и E2E-проверки
├── css/                     # Стили интерфейса
├── icons/                   # Иконки расширения
└── test/                    # Автоматические проверки
```

### Запуск тестов

Для полного локального прогона нужны Node.js и Python:

```powershell
node test/run-all-tests.js
```

Только JavaScript-проверки:

```powershell
node test/run-js-tests.js
```

Текущий полный набор включает 92 JavaScript behavior-теста и 41 исполняемую
Python smoke/security/audit-проверку; все 76 production JavaScript-файлов также
проходят `node --check`.

Push тега `vX.Y.Z` запускает release workflow: он прогоняет полный набор тестов,
проверяет совпадение тега с версией `manifest.json`, собирает ZIP и SHA-256 и
публикует GitHub Release с автоматически сформированными release notes.

Дополнительная информация: [test/README.md](test/README.md).

Для изменения runtime, storage schema или интеграций используйте
[docs/development-guide.md](docs/development-guide.md): там собраны инварианты,
матрица влияния и обязательные проверки перед выпуском.
