# UX-аудит маршрутов Grafana → DashBridge / Options / Test Runner

Дата: 2026-09-09. Проверка текущих исходников после исправлений F01–F12; эти исправления здесь не пересматриваются. Архитектура и владельцы runtime учтены. Ниже подтверждены подписи, переходы и контракты данных; влияние на ожидания пользователя — UX-оценка, а не результат наблюдения за пользователями. Живой браузер не использовался, код не менялся.

## U-MAIN-01. Общий режим снимков представлен переключателем конкретной панели

**Сейчас.** В заголовке панели рядом с «Сохранить снимок панели в PNG» и «Скопировать снимок панели в буфер» находится кнопка «Компактный снимок 1000×520: включён/выключен» (размер берётся из настроек). Нажатие меняет не только выбранную панель: режим синхронизируется на всех кнопках документа и сохраняется в общей настройке расширения. Размеры редактируются отдельно: Options → Grafana → «Компактный снимок» → «Ширина (px)» / «Высота (px)». Только там объясняется: «Используется для компактных снимков в Grafana, DashBridge и массовом сборе».

**Почему маршрут неясен.** Место кнопки и соседние действия обозначают конкретную панель, а область действия переключателя шире. Чтобы получить другой размер, пользователь должен обнаружить отдельно расположенные настройки.

**Текущий путь → проще.** Кнопка панели → неожиданно общий режим → Options для размеров → возврат к панели. Предложение: единое меню «Снимок» с режимами «Как на экране» / «Компактный (1000×520)», видимым пояснением «Общий режим для всех панелей» и пунктом «Размер компактного снимка…», ведущим непосредственно к настройке. PNG и буфер остаются явными выходами этого меню.

**Контракт и потребители.** MAIN владеет панельными кнопками: `js/content/grafana-panel-menu-runtime.js:520`, `:534`, `:538`; подпись формируется в `js/content/grafana-panel-capture-runtime.js:93`. `setPanelCapturePrepared` обновляет общий dataset и все кнопки, затем отправляет `dashbridgeCapturePreparedSettingChanged` (`:107`). Isolated content script проверяет разрешённый Grafana host и активный жест, пишет `chrome.storage.sync.grafanaCompactScreenshot` (`js/content/content.js:73`); storage listener распространяет изменения (`:59`). DashBridge также читает эту настройку (`pages/dashbridge/dashbridge.js:345`, `:378`). Размеры и общий охват описаны в `pages/options/options.html:240`, `:253`. При улучшении UI следует сохранить этот общий контракт, не превращая его молча в настройку отдельной панели.

## U-MAIN-02. Два «сохранения» рядом имеют разный срок жизни и не переносят одни и те же данные

**Сейчас.** Кнопка в заголовке direct Grafana с tooltip «DashBridge» открывает «Настройки графика». В модальном окне есть подсказка «Применяются только к этому графику» и кнопка «Сохранить». Эти изменения живут до перезагрузки документа. Рядом находится «Сохранить в DashBridge»: она открывает выбор профиля и добавляет ссылку на панель, но не переносит применённые временные визуальные настройки.

**Почему маршрут неясен.** «Сохранить» не сообщает о временном сроке жизни; соседнее «Сохранить в DashBridge» легко прочитать как сохранение уже настроенного вида. В действительности в профиль уходят URL, заголовок и стандартные размеры, без `tools`.

**Текущий путь → проще.** «DashBridge» → «Настройки графика» → «Сохранить» → «Сохранить в DashBridge» → профиль → «Сохранить». Предложение: назвать первую кнопку «Настройки графика», в direct Grafana использовать «Применить» с пояснением «Для этой панели до перезагрузки страницы». Вторую назвать «Добавить панель в профиль…», в диалоге пояснить, что добавляется ссылка, а временные настройки вида не переносятся. Перенос настроек можно обсуждать отдельной функцией; для устранения неоднозначности он не обязателен.

**Контракт и потребители.** Триггер MAIN: `js/content/grafana-panel-menu-runtime.js:512`, `:520`. Общая разметка модального окна: `js/shared/grafana-panel-settings-modal.js:579`; прямой consumer записывает `panel.__dashbridgeVisualState` и document Map (`js/content/grafana-panel-tools.js:2258`). Срок жизни Map явно определён в `js/content/grafana-panel-state.js:1`, реализация `:23`. Отдельная кнопка передаёт только `panelId` и `title` через `dashbridgeSavePanelRequest` (`js/content/grafana-panel-menu-runtime.js:541`, `:554`). Isolated dialog добавляет идентификатор/имя профиля и отправляет `dashbridge-save-grafana-panel` (`js/content/content.js:230`, `:286`). Service worker маршрутизирует запрос (`js/background.js:225`), владелец profile storage добавляет `{id, src, title, width, height}` и пишет local storage (`js/background-profile-storage.js:154`, `:157`, `:163`). Подпись общей модалки следует менять с учётом consumer: в DashBridge существует отдельный `onSave` для профиля (`pages/dashbridge/dashbridge-panel-tools-controller.js:277`).

## U-MAIN-03. Результат анализа скрывает собственные пороги и путь к настройкам копирования

**Сейчас.** Диалог «Анализ CPU — …» / «Анализ RAM — …» предлагает «Максимум за период», «Последнее значение», «Скопировать список», «Скопировать TOP-3». Цвета значений и текст копирования зависят от общих настроек Options → Grafana → «Анализ CPU/RAM»: «CPU Порог 🟨 (%)», «CPU Порог 🟥 (%)» и RAM-аналоги; «Шаблон для \"Весь список\"» / «Шаблон для \"TOP-3\"». В самом диалоге нет числовой легенды порогов и перехода к их настройкам. При этом соседние «Настройки графика» содержат другие параметры — «Порог на графике», «Значение порога», «Уведомлять о превышении».

**Почему маршрут неясен.** Из результата нельзя понять границы жёлтого/красного или найти источник скопированного текста. Ближайшая настройка с названием «порог» управляет другим механизмом, поэтому поиск через панельные настройки ведёт не к параметрам анализа.

**Текущий путь → проще.** Анализ → закрыть → искать настройки расширения → Grafana → «Анализ CPU/RAM» → изменить → снова открыть анализ. Предложение: в диалоге показывать фактические значения «Предупреждение ≥ …%, критично ≥ …%» и действие «Настроить анализ…» с переходом к конкретному разделу Options. Рядом с копированием — «Шаблоны текста…» в тот же раздел. Указать, что настройки общие. Панельный порог можно уточнить как «Линия порога этой панели»; значения двух механизмов не объединять.

**Контракт и потребители.** Isolated content script публикует `cpuWarnThreshold`, `cpuCritThreshold`, `memWarnThreshold`, `memCritThreshold` и шаблоны в MAIN dataset (`js/content/content.js:2`, `:15`, `:63`). MAIN читает их (`js/content/grafana-panel-menu-runtime.js:63`), создаёт интерфейс анализа (`:164`, `:179`, `:186`), вычисляет цвета (`:220`) и копирует текст (`:282`). Общий чистый helper владеет порогами и форматированием (`js/shared/grafana-panel-analysis.js:72`, `:79`). Options controls: `pages/options/options.html:257`, `:260`, `:279`; отдельный panel threshold contract: `js/shared/grafana-panel-settings-modal.js:242`. Новый переход из MAIN потребует разрешённого моста в isolated/extension context; прямой доступ к chrome API из MAIN не предполагается.

## U-MAIN-04. Переход из отладки Grafana в Test Runner теряет текущий дашборд

**Сейчас.** Popup → Grafana → «Отладочная» → «E2E Test Runner» создаёт новую вкладку runner без URL текущей страницы. В ней поле «URL Grafana дашбордов (по одному на строку)» заполняется последним сохранённым списком, если он есть. Запуск остаётся отдельным действием «Запустить тесты» с профилем «Быстрый» / «Полный».

**Почему маршрут длиннее необходимого.** Если пользователь открыл отладку на проблемном дашборде, он должен вручную перенести URL или заменить старый список. Удобство сохранённого набора полезно для регулярной проверки, но контекст текущей диагностики при переходе не передаётся. Автоматического запуска или подтверждённой ошибки выбора цели здесь нет.

**Текущий путь → проще.** Проблемная Grafana → Popup → «Отладочная» → runner → вернуться за URL → вставить/заменить старые URL → «Запустить тесты». Предложение: добавить «Проверить текущий дашборд…», передающее проверенный URL активной Grafana-вкладки в явно видимое поле runner; запуск оставить ручным. «Открыть Test Runner» сохраняет сценарий прежнего списка из нескольких URL. Не перезаписывать сохранённый набор одним фактом открытия runner.

**Контракт и потребители.** Подписи Popup: `pages/popup/popup.html:104`, `:229`; extension-page обработчик создаёт URL без параметров (`pages/popup/popup-grafana-debug.js:316`, `:319`). UI runner владеет полем (`pages/test-runner/test-runner.html:560`), профилем (`:568`) и кнопкой (`:589`). Восстановление из `chrome.storage.local.trLastUrls` — `pages/test-runner/test-runner-ui.js:701`; сохранение выбранной пользователем цели при запуске — `:502`. Передача URL — предлагаемый новый входной контракт, который должен иметь приоритет над восстановлением в поле только для контекстного перехода и проходить существующую проверку целей.

## Приоритет применения

Сначала U-MAIN-02: точные подписи и пояснения устраняют расхождение между «сохранить» и фактическим результатом без изменения storage-контрактов. Затем U-MAIN-01 и U-MAIN-03: сделать видимыми общую область действия и фактические параметры. U-MAIN-04 — отдельное сокращение маршрута диагностики. Объединение настроек или автоматический запуск проверок для этих улучшений не требуется.
