3. [Roadmap](roadmap.md) — актуальное незавершённое. [Октябрьский план](superpowers/plans/2026-10-12-extension-audit-and-work-plan.md) сохраняет evidence и статусы идентификаторов; исходные пункты не следует выполнять заново без сверки.

Не нужно снова исправлять находки из прежних аудитов: завершённые исправления сведены в [историю проверок](history/audit-results-2026-09-09.md). Исправление в рабочей копии не означает, что оно уже опубликовано.

## Как поддерживать порядок

В roadmap остаётся только незавершённое. После реализации убрать задачу, обновить контракт в архитектуре и постоянные тесты. Не создавать ещё один полный аудит для записи исправления нескольких пунктов.

Повторные июльские/августовские отчёты и статические инвентари удалены; сохранённые
исторические документы помечены отдельно. Актуальные размеры и загрузочные связи
получают через `scripts/check-module-boundaries.js`, `scripts/check-dependency-contracts.js`
и GitNexus. Локальные логи принадлежат игнорируемому `test-results/`; старый repro,
ожидающий дефект, не является тестом исправленной версии.

Для необычного решения фиксировать функцию пользователя, причину, контекст,
владельца состояния, scope, cleanup, альтернативы и ограничения. Ссылки вести на
файл и имя функции/теста, не на быстро устаревающий номер строки. Тест подтверждает
только свой сценарий; локальная fixture не доказывает рабочую интеграцию.
Обоснование не заменяет guard и не разрешает игнорировать новое расхождение с кодом.
