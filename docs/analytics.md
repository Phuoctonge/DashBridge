# Обезличенная аналитика DashBridge

## Назначение и границы

Аналитика помогает приоритизировать поддержку функций у небольшой внутренней
аудитории. Она всегда включена, но собирает только псевдонимные агрегаты. На
клиенте запрещены IP-адреса, логины, имена, почта, URL и домены, названия
профилей/панелей, Jira keys и тексты, TDM/Recorder payload, содержимое буфера и
произвольные сообщения ошибок. Сервер этапа 2 обязан также отключить access
logs с IP или настроить их немедленную анонимизацию.

`installationId` создаётся локально через `crypto.randomUUID()` и сохраняется
отдельным ключом `dashbridgeInstallationId` в `storage.local`, независимо от
очереди событий. Перезапуск service worker, штатное обновление по прежнему пути
и миграция внутренней схемы сохраняют ID. Регистрации на сервере нет. Это
псевдоним, а не анонимность против владельца устройства: полное удаление
расширения/очистка browser storage или новый профиль создают новый ID, а
копирование профиля браузера может перенести прежний ID.

## Контракт события

Service worker принимает только объекты из статического каталога
`js/shared/analytics-contract.js`. Неизвестная функция, signal, dimension,
значение dimension или дополнительное поле отклоняются целиком.

Сигналы имеют разный смысл:

- `used` — пользователь вызвал функцию;
- `changed` — изменил переключатель или режим;
- `configured` — функция сохранена в состоянии и может работать без новых кликов;
- `effective` — runtime подтвердил применение; одинаковое подтверждение хранится
  не чаще одного раза в день на installation/feature/dimensions;
- `outcome` — безопасная категория результата (`success`, `partial`,
  `cancelled`, `invalid_input`, `no_data`, `error` и т. п.);
- `lifecycle` — установка, обновление или дневная активность.

Сбой общей команды применения инструментов панели записывается один раз как
`internal.panel_tools_apply`, а не размножается по всем включённым функциям.
Dimension `failure` принимает только закрытые диагностические категории
(`runtime_dependency_missing`, `visual_verification_failed`,
`legend_apply_failed`, `timeout`, `unexpected_exception`). Текст исключения,
stack trace, URL и данные панели в аналитику не отправляются. Старые события без
`failure` нельзя достоверно классифицировать задним числом.

В очереди запись содержит только `eventId`, начало часа UTC, `featureId`,
`signal`, разрешённые dimensions, счётчик и версию расширения. Количества
пользовательских сущностей передаются только диапазонами `1`, `2_5`, `6_10`,
`11_plus`.

## Нагрузка и доставка

События агрегируются по часу до записи. Extension pages используют один
делегированный обработчик `click` и `change`; snapshot читает уже существующий
storage не чаще раза в день и не обходит DOM/iframe/сеть. Очередь ограничена
2000 агрегатами, отправка — пачками до 100 не чаще раза в час, с
экспоненциальным backoff и восстановлением `inflight` после остановки MV3
worker. Периодический `chrome.alarms` имеет случайный начальный сдвиг; за один
wake-up отправляется не больше одной пачки, поэтому большой офлайн-хвост не
создаёт длительную фоновую передачу. Если очередь пуста, запроса нет. Ошибки
аналитики всегда fail-open для пользовательской функции.

Production endpoint — `https://analytics.tongehub.com/v1/events/batch`.
Запрос отправляется без credentials и referrer и имеет вид:

```json
{
  "schemaVersion": 1,
  "installationId": "локально-созданный-uuid",
  "droppedAggregates": 0,
  "events": [
    {
      "eventId": "uuid",
      "periodStart": "2026-09-03T10:00:00.000Z",
      "featureId": "grafana.panel.fill_removed",
      "signal": "effective",
      "dimensions": { "surface": "dashbridge", "state": "enabled" },
      "count": 1,
      "extensionVersion": "2.4.3"
    }
  ]
}
```

Срок серверного хранения определяется на этапе 2. Практический старт — 12
месяцев для почасовых агрегатов при запрете сырых HTTP-логов; после первых
месяцев его можно сократить или увеличить по фактическому объёму.

## Добавление события

Сначала добавьте стабильный `featureId`, signals и закрытый набор dimensions в
контракт. Затем вызывайте только `DashBridgeAnalytics.track/opened/changed` или
`outcome`. Нельзя передавать динамические строки даже под новым нейтральным
именем поля. Для сохранённых функций добавьте безопасный дневной snapshot, а
для runtime-функций — коррелированное подтверждение от владельца применения.
Обязательны отрицательные тесты на лишние поля и чувствительные значения.

## Изоляция тестовых запусков

Browser smoke всегда создаёт новый временный профиль Chromium, поэтому не
должен обращаться к production collector: иначе каждый прогон выглядел бы как
новый анонимный пользователь. Runner загружает временную копию расширения и
меняет endpoint только в этой копии на локальный HTTP-приёмник `127.0.0.1`.
Так проверяется реальная отправка из service worker без изменения DNS,
production-конфигурации или сетевого поведения пользовательского расширения.

## Разработка и публикация collector

Локальная админка использует отдельную синтетическую SQLite и loopback-only
dev gateway. `scripts/Start-AnalyticsDev.ps1` запускает её в Node watch; с
production endpoint и `/data` этот режим не связан.

Production использует постоянный `node:24-alpine` с read-only bind mount кода,
а не сборку application image. Административные assets читаются на каждый
запрос, поэтому HTML/CSS/client JS применяются без остановки ingestion.
Публикация backend выполняет проверенную загрузку, backup, короткий restart,
health-check и rollback; SQLite находится в отдельном `/data` и не входит в
release. Compose и root helper не обновляются через ограниченный deploy-канал.
